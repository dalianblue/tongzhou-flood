## 两次淹没事件

- **7/13 台风暴雨型**：台风"巴威"(BAVI/2609) 7/11 深夜正面过境桐洲岛（最近 13km，STS 级），
  流域两日暴雨 **206mm**（富春江电站，7/11~12），富春江坝下 24h 均值冲至 10.78m 全年最高，
  新桐乡真实峰 7.61m。巴威 7/10 距岛 1000km+ 时路径已明确 → 台风预警可提前 48h+
- **8/9 台风外围型**：台风"白海豚"(DOLPHIN/2613) 路径最近 205km（未过境），外围雨带
  致渌渚江支流暴涨（渌渚镇 6h +1.42m），坝下仅 ~8m，新桐乡真实峰 ~7.11m。
  当日 11.31m 读数为传感器故障（下游不可能高于上游 4m），已物理校验剔除

淹没阈值：新桐乡 ≥6.5m 黄 / ≥7.0m 红。

### 两次事件对比：归因（含流域雨量，2026-09 补充）

| | 7/13 巴威正面过境 | 8/9 白海豚外围 |
|---|---|---|
| 流域雨量（富春江电站，事件过程） | **206mm / 2天** | **242mm / 3天** |
| 肖岭水库（桐庐，渌渚江侧） | 157mm / 2天 | 8/9 单日 190mm |
| 坝下 24h 均值峰 | **10.78（全年最高）** | 8.21 |
| 坝下 ≥8.6（红泄洪级）时长 | **36h** | 0h |
| 渌渚镇支流 6h 涨幅 | +1.01 | +1.42 |
| 岛上山溪 6h 涨幅 | +0.14（溪流受基流/上游小库缓冲，**非降雨代理**） | +0.46 |
| 新安江电站水位 | 7/13 起入库 +1.0m（上游来水） | 全程持平（未放水） |
| 新桐乡峰值 | **7.61** | 7.24 |

判断（经雨量数据修正）：**两次淹没都是自然暴雨洪水，水库"过度预泄"的指控不成立**——

- 7 月巴威对流域是暴雨台风：7/11~12 坝前区域 206mm。富春江电站是日调节径流电站，
  库容拦不住区间+兰江来水，坝下 10.78 的峰**大部分是暴雨的被动过流**；主动预泄的
  证据很小（7/11 坝前仅下降 0.26m）
- 新安江（有巨量库容）在 7 月拦洪入库仅抬升 1m，已尽拦蓄之责；8 月无放水，无闸可关
- 早先"本地几乎没下雨"的推断是被山溪站误导——山溪 6h 涨幅 +0.14 是溪流缓冲的结果，
  不是降雨为零（流域雨量站的引入纠正了这一点）

对预警模型的启示：暴雨过流型事件坝下爬升快、起步早，黄警天然提前量大（7 月 +19h）；
难的是 8 月那种坝下不动、支流缓涨的型式——为此已把渌渚镇黄阈值降至 0.5（微涨
即黄，首黄 15h→39h）、新增渌渚镇动量红判据（首红 5h→9h）。

### 汛末对照：9 月真实脉冲 vs 潮汐涟漪（节气门控的由来）

处暑（8/23）之后汛情基本结束，但 9 月实测数据里有两个表面相似、本质相反的案例：

| | 9/2 渚渚江脉冲 | 9/10~11 潮汐涟漪 |
|---|---|---|
| 渌渚 6h 涨幅 | **+2.37（真实暴涨）** | +0.92（常规半日潮波动） |
| 渌渚水位 | **冲到 7.89** | 仅 5.31（低基面） |
| 新桐乡 | **6.46——距黄警阈值仅 4cm** | ~5.3，远离阈值 |
| 本质 | 处暑后残余的 10% 汛情 | 低流量期潮汐上溯，渌渚水位与岛上脱钩 |
| 门控后 | **照常报警（处暑~白露相位，渌渚≥6.5 涨幅有效）** | 不报警（渌渚<6.5，涨幅判据关闭） |

这正是"节气 + 水位"联合门控的设计依据：单用日期会漏掉 9/2 型脉冲，单用涨幅判据会
被潮汐涟漪天天误触发。处暑~白露之间用渌渚 6.5m 作水位配合门即可把两者分开；白露
（9/7）之后汛情概率 <5%，预测判据全停，只留新桐乡实测兜底。顺带的收益：回测样本里
处暑后（8/23~8/31）的潮汐误报也被同一道门滤掉，黄警误报 72h → 59h。

### 调度员复盘：接到台风预报后，能否避免桐洲岛被淹

（经流域雨量数据修正：早先"7 月可通过封顶泄量避免淹没"的结论不成立——那建立在
"本地几乎没下雨"的误判上。）

**7 月（巴威正面过境）：大概率避免不了，能做的只有削峰。**

- 巴威对流域是暴雨台风（坝前 206mm / 2 天）。富春江电站是**日调节径流电站**，库容
  拦不住区间+兰江的暴雨径流——水必须过坝，坝下 24h 均值 10.78 的大部分是被动过流，
  "封顶 9.31 就不淹"在物理上不成立；
- 新安江（真正的蓄洪库）已尽拦蓄之责：入库仅抬升 1m，下游的 7 月洪峰主要不是它放的；
- 调度员手里只剩两件小工具：**日内避潮错峰**（7/12 泄洪峰距闸口潮峰仅 3h，挪到落潮段
  可削下游峰一截）和**提前预泄的量**（7/11 坝前仅降 0.26m，预泄幅度其实不大）。
  结论：7 月淹没以天灾为主，人为可消除的成分有限。

**8 月（白海豚外围）：水库无解，只能减压。**

肇事者是渌渚江支流雨带（肖岭 8/9 单日 190mm），干流只是背景水位（坝下 8.2 为兰江被动
过流），新安江全程未放水——无闸可关。可做的只有支流峰时段（8/10 07:00 前后）把富春江
坝下从 8.5 压到 ~7，渌渚峰约降 0.5m，把新桐乡从 7.24 压向红线附近；但库容只够错峰几
小时。8 月的"避免"不在水库手里：要么岛上工程防御，要么靠提前 39h 的预警组织撤离。

**结论：两次淹没都是自然暴雨洪水，调度可消除的成分有限（避潮错峰、支流峰时让路可
削峰零点几米）——真正可靠的防线是提前预警与岛上防御，这正是本系统的价值所在。**

## 台风因素 (typhoon.py)

数据源：中央气象台台风网公开接口（typhoon.nmc.cn，JSONP，无需登录）。

```bash
python3 typhoon.py --live      # 当前活动台风 + 72h预报路径距岛威胁
```

- `--check` 风险卡自动附带台风段：活动台风当前距离 + 各机构 72h 预报路径最小距岛距离
- **预备级（蓝）**：预报 72h 内距岛 ≤500km → 提示"水库大概率预泄 + 支流涨水，提前巡查"。
  不自动改水位风险等级——水库预泄本身已由坝下判据捕捉（泄洪型黄警），且纯距离阈值
  不可靠（白海豚 205km 淹 / 美莎克 866km 未淹）
- `--demo` 复盘自动显示"距岛最近台风"列（从本地轨迹缓存读取，零API）

## 使用

```bash
python3 dashboard.py                  # 网页监控台 (推荐): 风险卡+72h水位曲线+台风+事件复盘
python3 flood_warning.py --check      # 实况风险卡 (4次API, ~2分钟, 间隔26s限频)
python3 flood_warning.py --backtest   # 历史样本回测 (零API)
python3 flood_warning.py --demo 2026-08-09   # 事件复盘 (零API)
```

Dashboard 启动后打开 http://localhost:8787 。后台每小时自动拉取一次实况并缓存
（`data/live_cache.json`，重启不丢），打开网页即时显示最近结果；拉取失败时保留
上次缓存并标红提示。首次启动无缓存时第一次拉取约需 2 分钟（接口限频），页面会
显示进度。事件复盘图表用历史样本（零 API）。

**夜间值守**：6 次过淹中 4 次发生在深夜到清晨（02~07 时）。睡前点一次"开启报警声"，
页面常开（旧手机/平板放床头、调高音量），等级升黄/红时自动响铃（红警持续响）、
标签页标题闪烁；报警期间后台自动加密到每 30 分钟拉取一次（仍守接口限频）。

## 预警规则与回测效果

| 级别 | 判据 |
|---|---|
| 节气门控 | 主汛期 6/15~处暑(8/23) 全判据；处暑~白露(9/7) 涨幅/动量判据需渌渚≥6.5（滤潮汐涟漪，保真实脉冲）；白露后仅新桐乡实测现报级 |
| 黄-泄洪 | 坝下24h均值≥7.0 且 渌渚6h涨≥0.3 |
| 黄-支流 | 渌渚6h涨≥0.8 / 渌渚镇涨≥0.5 / 山溪涨≥0.6 |
| 红-动量 | 渌渚+6h涨幅 ≥7.3（峰值外推） |
| 红-支流动量 | 渌渚镇+6h涨幅 ≥8.3（峰值外推） |
| 红-泄洪级 | 坝下24h均值≥8.6 或 瞬时≥10.0 |
| 顶托 | 闸口≥6.0 时黄升红 |
| 现报级 | 新桐乡≥6.5/7.0（任何节气生效）；已过淹没阈值则保持不降级 |
| 复淹警戒 | 近 48h 曾过淹且近 6h 新桐乡 ≥5.5 → 退水期半日潮反复越阈，**暂勿回岛低洼处**（任何节气生效） |
| 退水确认 | 新桐乡持续 6h < 5.5 → 12h 内复淹概率 <11%（实测 89% 安全），**可回岛查看** |

**居民视角**：首黄不是关键指标——连日下雨、水位上涨居民自己有感。系统真正要回答的是
“什么时候必须撤、什么时候能回来”：红灯/现报级=撤离信号；退水期即使涨幅判据安静，
半日潮仍会把水位反复顶过 6.5（2026 年 6 次过淹中 4 次是复淹，此前进水时刻模型还是
绿灯——复淹警戒就是补这个洞）；持续降到 5.5 以下才是可回岛信号。

回测（6/25~8/31，1632h）：4 次过阈事件全中，**6 次过淹时刻（含 4 次退水期复淹）全部亮灯**。
首黄提前 19h/48h/39h/48h，首红提前 11h/48h/9h/48h。误报口径说明：黄以上 333h 中
“报警后 24h 无过阈” 150h，其中约 133h 属退水期复淹警戒带（该带按“12h 内真复淹”口径
命中 49%，作用是整个退水期禁止回低洼处，属保守设计）；剔除警戒带后的常规误报与
此前口径一致（红误报 35h）。

节气门控的设计依据与 9 月两案例对照见前文"汛末对照"一节。

渌渚镇黄阈值 0.5 与红-支流动量 8.3 是针对 8/9 型"浅而久"支流事件的改进：支流对台风外围
雨带响应是缓涨型，微幅异常比暴涨早 1~2 天可见（8/9 事件首黄 15h → 39h，首红 5h → 9h），
代价是黄误报 +10h、红误报 +12h。

### 雨量为什么只做展示、不进判据（实测过，负收益）

用 2026 全汛期日雨量（两站均值）对"雨量进规则"做了两种检验：

- **当先导判据**（近两日雨量≥50mm 报警）：不如水位——雨量是日粒度且日终才结算，
  先导提前量 7 月 13h / 8 月仅 2h，均晚于现行水位首黄（19h / 39h）。支流微涨比
  暴雨峰值早见，水位是"正在发生"的信号，雨量是"刚过去"的信号；
- **当误报过滤门**（涨幅类黄警需近两日雨量≥20mm）：黄误报 59h 中 54% 确实发生在
  无雨期，门可砍掉约一半误报——但代价是 8 月型首黄 39h → 15h、7 月 19h → 11h，
  用提前量换误报削减净收益为负。

最终定位：雨量用于展示与事件归因（"为什么淹"），水位用于预警（"提前喊"）。无雨误报
场景（非汛期潮汐涟漪）已由节气门控覆盖。

## 样本外验证（2025 年，收割重放）

规则在 2026 年 6~8 月样本上校准，2025 年全汛期（6/1~10/14，8 站 × 5min，31 万行，
`--harvest-year` 从接口收割）做真正的样本外重放：

**命中**：2025-06-15 梅雨洪水（新桐乡峰 **8.28m**，比 2026 两次都深，过淹 37h）——
首黄提前 **9h**、首红提前 **3h**、过淹时刻已红灯、过淹前 3h 已红灯。无漏报。

**修正**：样本外暴露出支流动量红判据（8.3）会误撤——2025 年 6/28、7/27~28 渌渚镇孤涨
（渌渚 4.88~5.35）触发撤离级红警但岛未淹。修正为**支流动量红需渌渚（干流）≥5.5 佐证**
（真事件首红时渌渚 5.85/6.66，误撤时全在门下；物理依据：干流低水位会稀释支流峰，孤涨
不淹岛）。加门后 2026 四事件首红提前量不变，2025 红误报 32h→18h。

**误报（居民视角）**：

| | 2025 样本外 (136天) | 2026 样本内 (68天) |
|---|---|---|
| 黄误报 | 107h / 26 天（约每 5 天一次） | 150h / 20 天（约每 3 天一次） |
| 红误报（撤离级） | 18h / 2 天 | 28h / 6 天 |

注：误报口径含退水期"现报级不降级"与复淹警戒带的保守保持（岛仍在水中或刚退），
真正的"撤离了却没淹"在 2025 年加门后约为 0~1 次。黄级偏啰嗦（多为电站调峰 1~2h 毛刺）
是已知代价——黄=留意，不是撤离。

**遗留短板**（明年汛期优先验证）：快涨型梅雨事件红警提前量仅 3h（2025-06-15）；
2024 级极端（9.61m）下定量估算未经验证。

## 已发现并修复的缺陷（记录备查）

### 代码缺陷

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 报警期 30 分钟加密拉取实际不生效 | `_stale()` 过期线固定 1 小时：报警时 30 分钟醒来、缓存未"过期"又睡回去，实际仍 ~1 小时一拉 | 黄/红时过期线降为 30 分钟 |
| 上游渌渚站缺失会弄瞎撤离判据 | 新桐乡故障清洗规则"与渌渚差>2m 剔除"在渌渚整站缺失时把 xt 全部剔成 NaN，现报级失效——恰在最需要它的数据残缺时刻 | 渌渚未知时保留 xt（宁信实测），归档+实况两处 |
| 历史收割主站全部返回空 | 迭代站字典时误用键（站名 baxia/luzhu…）当站号发给接口，溪站恰好键为真站号所以"部分正常"，掩盖了错误 | 改用站号列表 |
| 断点续收崩溃 | 被中断的收割留下 0 字节 CSV，重跑时 `read_csv` 抛 EmptyDataError | 空文件容错 |
| 收割全部空返回（间歇性） | 多个收割进程并发超过接口 ≤3 次/分限频，服务端不报错、静默返回空 | 单进程运行 + 空结果重试 |

## 边界

### 历史参照：2024-06-25~26 特大洪水（官方水文简报验证）

水位接口只回溯到 2025 年中，但**浙江省水文简报**（`sqfb.slt.zj.gov.cn:30050` 水雨情平台
可下载，2024 年 6/25~27 共 18 期已存档 `data/bulletin_2024/`）提供了事件全过程的官方
站点时序。岛上结果：6/26 凌晨超 9.0m 房屋积水、10:30 峰 **9.61m（1997 年以来最高）**。

对模型的验证与启示（2024 型为兰江主导的梅雨洪水，与 2025-06-15 同型放大版）：

1. **黄级链条成立**：上游首警（梅城 6/25 11 时超警）领先岛峰 **23.5h**；三河/桐庐超警
   （6/25 20 时）领先岛峰 14.5h、领先岛进水约 4~6h。模型的"上游涨→黄"设计在此型事件
   有充分提前量；
2. **官方红级救不了岛（关键反证）**：官方"保证水位"级红色信号 6/26 02 时才出现，与岛
   凌晨进水几乎同时——**等官方红警再撤已经晚了**。这正是本模型把红级锚定"新桐乡实测
   6.5/7.0 + 动量外推"而非官方保证水位的原因，2024 事件反证了该设计；
3. 局限：简报无坝下/渌渚/新桐乡逐时序列，泄洪型与动量判据无法数值重放，仅验证了
   上下游时序逻辑与撤离窗口。

- 规则阈值基于 2026 年 6~8 月 4 次过阈事件校准，样本少，其他年份/量级的事件可能误报或漏报
- 节气用公历近似日期（每年 ±1 天）。白露关停已用雨量站 2023~2026 四年数据验证：白露后最大日雨量 53mm（2022 秋台风梅花），仅为淹没量级（190~242mm/过程）的 1/4~1/8；极端尾部（如 2013 年 10 月台风菲特型，接口无该年数据）由全年生效的新桐乡实测现报级兜底
- 台风只做预备级提示，不参与水位风险等级判定（无历史预报样本可校准升级规则）
- 依赖公开接口，`--check` 有限频（约 2 分钟），台风接口异常时自动降级为无台风段
- 传感器偶发故障读数靠物理校验剔除（下游高于上游），不能覆盖所有故障模式
